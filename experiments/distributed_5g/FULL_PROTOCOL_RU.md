# Полная перспективная проверка реализованного метода, 11 ноября 2026

Протокол фиксируется до тестовых измерений. Три независимых runner Open5GS 2.7.6,
seeds 89501–89503. На каждом: 600 нормальных окон обучения (seed+1000),
600 отдельных нормальных окон калибровки (seed+2000), затем 3600 новых тестовых
окон, 32 NF. Окно имеет минимальную длительность 1 с; фактическое время зависит
от измерений и подтверждения распределённых решений, поэтому 3600 окон не
называются ровно одним часом. По 19200 train/cal и 115200 test наблюдений на запуск.

Isolation Forest по SBI, с контекстом и с полным набором признаков обучается заново
только на нормальных измерениях; 256 деревьев, max_samples=256, alpha=0.001.
Пороги выбираются на отдельном нормальном запуске. В модель не входят метки,
идентификаторы эпизодов, NF или сценариев. Замороженные зональные пороги и
контрольные параметры остаются из подготовительного этапа: это проверка текущего
метода с новым обучением IF, а не переоптимизация всех компонентов.
Исходные архивы компонентов закреплены SHA-256 в workflow. После начала теста
никакие параметры не меняются. Неудачи и пропуски сохраняются.

Полный существующий план из robustness_5g/design.py: 36 эпизодов на запуск,
по четыре S1, S2, S3, S4, C, F, R, D и четыре варианта G (fast, slow,
intermittent, inside_permit). Всего 108 эпизодов, 1410 положительных NF-окон.
Смена порядка сценариев определяется новым seed. Штатный фон включает четыре
режима нагрузки, перезапуски NSSF, разрешённые изменения адреса/статуса и
перерегистрацию. Фактические HTTP-события и моменты применения сохраняются.
Положительная метка G inside_permit означает скрытое воздействие; действительное
разрешение может делать его неразличимым для детектора. Такой пропуск не исключается.

Онлайн: наблюдение → признаки → замороженные IF → 32 ведомых → четыре зональных
ведущих → координатор. 37 самостоятельных процессов в пяти сетевых пространствах
имён на одном физическом runner. IF вычисляется общим сборщиком; ведомые получают
его результат. Распределены проверки, накопление и принятие решения; обучение и
вычисление IF не объявляются распределёнными.

Основные сравнения на одинаковых данных: rules, IF_SBI, IF_CONTEXT, FULL_HYBRID.
Дополнительные: WITHOUT_MINING (тот же гибрид с тем же восстановлением, но без IF),
ORIGINAL_HYBRID (без восстановления после трёх нормальных окон). Разность
FULL_HYBRID/WITHOUT_MINING измеряет вклад IF при неизменных остальных компонентах.
Правила baseline уже определены в live_5g/evaluate.py и не усиливаются после теста.

Показатели: TP/FP/FN/TN, полнота окон, precision, FPR, наличие новой тревоги в
эпизоде, задержка новой тревоги в секундах и окнах, разрез по сценариям и запуску.
Для IF — average precision по непрерывному anomaly margin. Для конечного
состояния гибрида непрерывная шкала не определена; PR-AUC не подменяется числом
из бинарных решений. Целевой FPR ≤0.1% проверяется, но не гарантируется.
Unknown и потеря доступности учитываются отдельно и не засчитываются в TP.
Окна зависимы, независимых повторов три; интервалы по отдельным окнам не являются
доказательством статистической значимости. Метрики публикуются для каждого запуска.

Аудит: полнота сетки, отсутствие пересечения train/cal/test, хеш модели,
повторный расчёт IF, сверка чисел запросов/ошибок/задержек с исходными транзакциями,
проверка расписания меток и независимая арифметика зонального накопления/сброса.
Контрольный протокол и отказы узлов проверяются также существующими регрессионными
тестами. Локальная обработка свидетельств не заявляется независимо реализованной
в этом аудите. Накладные расходы: время обработки иерархии, CPU процессов и
выборочный RSS; отдельно затраты сборщика. Причинная добавленная задержка без
парного monitor-off эксперимента не заявляется.

Границы: работающий NRF и NSSF с зарегистрированными исследовательскими клиентами;
S3 — отказ отдельного исследовательского consumer, не эксплуатация CVE AUSF.
Контроль конфигурации и HMAC программные; нет аппаратной аттестации, UE/RAN/PDU,
межмашинной задержки или автоматического выбора нового ведущего. Полный здесь
означает совместную проверку всех реализованных компонентов и сценариев стенда,
а не всех возможных атак 5G или всех алгоритмов, перечисленных в диссертации.

Архив сохраняет одноразовый лабораторный ключ разрешений нагрузки для повторной
проверки подписей уже завершённого опыта. Он создаётся специально для этого
прогона и не является эксплуатационным ключом. Конфигурации/ключи соединений
действующих детекторов и ключ контрольного канала не публикуются.
