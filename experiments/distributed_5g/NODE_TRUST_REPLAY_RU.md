# Компрометация одной сетевой функции

Один запуск воспроизводит десять исходных типов на записанной телеметрии и отдельную синтетическую последовательность S10 для slot-4. Модель и разметка архива сохраняются. Две серии имеют независимую шкалу времени.

В S10 моделируется утрата доверия к узлу. Сначала состояние узла меняется только в контрольной разметке. Затем его конфигурация отклоняется от согласованной. Узел сначала сообщает свою изменённую конфигурацию, затем сообщает штатную. Независимый наблюдатель моделируется отдельно и временно теряет видимость. После восстановления штатной конфигурации контроль вновь подтверждает согласованность. Разрешённая смена конфигурации включена в нормальный фон.

Символы A, B и X обозначают абстрактные состояния. Функция решения получает ожидаемое состояние, сообщение узла и показание наблюдателя. Фаза и истинное состояние доверия используются только для оценки. Отсутствие наблюдения регистрируется отдельно. Остальные 31 функции вне области этого дополнительного контроля. Потеря доверия с прежними измерениями остаётся скрытой. Результат S10 характеризует заданную модель наблюдаемости; архивные метрики десяти типов подсчитываются отдельно.

Запуск с подготовленным архивом и каталогом модели:

```sh
python -m experiments.distributed_5g.node_trust_replay data/90301 frozen report
```

Рабочий процесс `node-trust-replay.yml` загружает исходные материалы, проверяет контрольные суммы и публикует `report.json` с отдельными результатами и `S10.csv` с наблюдениями, решениями и контрольной разметкой.
