# Распределённая зональная иерархия детекторов 5G

Реализованы самостоятельные HTTP-процессы трёх уровней. Состав проверяемого развёртывания — 32 ведомых детектора, 4 зональных ведущих по 8 NF и один координатор. Каждый процесс имеет собственный адрес, ключи входящих соединений, очередь исходящих отчётов и файл состояния.

| Уровень | Получаемые данные | Выполняемая работа |
|---|---|---|
| Ведомый NF | Локальный вектор наблюдения, разрешение нагрузки, доступное контрольное свидетельство | Пороги нагрузки, правила профиля и маршрута, проверка разрешения, подписи, свежести, сессии и повтора |
| Ведущий зоны | Аутентифицированные краткие отчёты назначенных ведомых | Медиана и MAD своей зоны, накопление отклонений для каждой NF, полнота состава зоны |
| Координатор | Зональные решения и состав пропавших участников | Проверка соответствия топологии, объединение результатов, указание недоступных зон и NF |

Первичные векторы направляются ведомым. Контрольные ключи и сырые признаки не передаются координатору. Ведущему достаточно числа запросов, признака разрешения и локальных диагностических флагов. Итоговые признаки безопасности, доступности и неопределённости сохраняются раздельно.

## Передача и состояние

Сообщения связываются HMAC-SHA256 с отправителем, получателем, эпохой развёртывания и номером последовательности. Принимаются только назначенные участники. Повтор последнего идентичного сообщения подтверждается без повторного вычисления. Подмена содержимого и конфликт последовательности отклоняются.

Результат обработки, номера последовательностей и исходящая очередь сохраняются атомарной заменой файла до подтверждения запроса. При перезапуске узел продолжает с сохранённым состоянием. Очередь ограничена четырьмя отчётами, переполнение создаёт обратное давление. Временно недоступный родитель повторно опрашивается. Окончательно отклонённые отчёты снимаются с очереди с увеличением счётчика отказов.

Сборщик задаёт начало окна. Зона закрывает его после получения всех участников либо по сроку ожидания 8 секунд. Координатор ожидает зоны до 12 секунд. Отсутствие ведомого приводит к availability/unknown. При неполном составе зоны накопители сбрасываются, поскольку изменился набор соседей. Локальные тревоги остаются в результате. При отсутствии ведущего вся назначенная ему зона отмечается недоступной. Закрытые окна не пересчитываются поздними отчётами.

В каждом процессе обрабатывается одно активное окно. Сборщик дожидается результата координатора перед переходом к следующему. При отказах это увеличивает длительность цикла. Отсутствие самого сборщика и резервирование координатора требуют отдельного эксплуатационного решения.

## Запуск отдельного узла

```powershell
python -m experiments.distributed_5g.node --config PATH_TO_NODE_CONFIG.json
```

`deploy.configure` формирует отдельные конфигурации и уникальные ключи связей. `deploy.Deployment` запускает эти конфигурации самостоятельными процессами на одном компьютере для проверки. Для размещения на нескольких машинах задаются доступные адреса и порты узлов, URL родителей и сборщика, а также локальные пути `state_file` на соответствующих хостах. Каждый процесс запускается приведённой командой на своей машине. Принадлежность NF зонам задаётся явно и проверяется на пересечения.

Рабочие конфигурации содержат ключи и хранятся в каталоге развёртывания. Их нельзя включать в публичные артефакты. HTTP-транспорт обеспечивает подлинность и целостность прикладных сообщений посредством HMAC. Для конфиденциальности между машинами требуется защищённая сеть или TLS-прокси. Ведомый монитор и источник наблюдений входят в доверенную вычислительную базу.

## Подключение к живому Open5GS

```powershell
python -m experiments.distributed_5g.live --seed 85133 --out evidence/test --frozen evidence/frozen --zone-models zone_models.json
```

Используется существующий сборщик ACCUM и его параметры стенда. После каждого окна признаки передаются самостоятельным ведомым, а зональные результаты записываются в `distributed_predictions.jsonl`. Часы ведомого используются для проверки свежести в живом режиме. Время передачи по сети входит в возраст свидетельства. Процессы запускаются и завершаются вместе с экспериментом. Для этого запуска нужны работающий Open5GS, замороженный набор моделей предыдущей серии и заранее откалиброванные модели зон.

## Проверка на сохранённых наблюдениях

```powershell
python -m experiments.distributed_5g.replay --calibration calibration.zip --evidence evidence.zip --out replay_output --windows 3600
python -m pytest experiments/distributed_5g experiments/accumulation_5g -q
```

Калибровка зон использует полностью штатные окна более раннего архива. Пороги накопления вычисляются для каждой зоны отдельно. Они сохраняются в `zone_models.json`. Во время воспроизведения ведомые используют исходное время оценки контрольного свидетельства, а сетевые сообщения проверяются по текущим часам. Этот режим явно задан в конфигурации и отделён от живого режима.

Проверка проходит через настоящие HTTP-соединения и отдельные процессы. Для каждого NF-окна результат сравнивается с расчётом исходного ACCUM, применённого отдельно к тому же составу зоны. Тесты проверяют изоляцию зон, отказ ведомого, отказ ведущего, восстановление процесса, подмену сообщения и сохранение защиты от повторов после перезапуска.

Многомашинные задержки и свежий прогон Open5GS с распределённой версией требуют отдельного измерения. Ранее опубликованные показатели полноты и FPR центрального ACCUM не переносятся автоматически на новую зональную конфигурацию.
