# Независимый вклад контрольного отчёта КИЕ

Опыт выполнен 8 ноября 2026 года. Три последовательных повтора на одном стенде
Open5GS 2.7.6, seeds 9101/9201/9301, по 160 проверок: всего 480.
Каждый повтор создаёт новые процессы исследовательской NF и наблюдателя,
регистрацию в настоящем NRF, ключ и случайные nonce. Это не 480 независимых
стендов и не повторная оценка ML-гибрида предыдущей серии.

## Что изменено

Наблюдатель читает фактическую конфигурацию с диска отдельным процессом.
Исследовательская NF читает её при каждом HTTP-запросе: изменение конфигурации
меняет ответ ALLOW на DENY. Сохранённый ответ подтверждает применение состояния;
он не передаётся детекторам. Это устраняет прежнее дублирование нормативного
профиля. Во всех 480 случаях хеш применённой конфигурации совпал с измерением
наблюдателя. NRF читается независимо по HTTP/2, профиль остаётся неизменным.

Сравниваются B — контроль профиля NRF; O — B плюс независимое наблюдение;
K — O плюс проверка HMAC-SHA256. Оба варианта O и K проверяют nonce, экземпляр
NF и возраст отчёта. Поэтому вклад HMAC отделён от проверки свежести.

## Измерения

Числа — количество тревог, по 60 проверок каждого условия.

| Условие | B | O | K |
|---|---:|---:|---:|
| Нормальное состояние | 0 | 0 | 0 |
| Разрешённое обновление | 0 | 0 | 0 |
| Изменённая конфигурация, честный отчёт | 0 | 60 | 60 |
| Подстановка нормального хеша в свежий отчёт | 0 | 0 | 60 |
| Повтор старого подлинного отчёта | 0 | 60 | 60 |
| Реальная задержка подлинного отчёта более 0,25 с | 0 | 60 | 60 |
| Старый нормальный отчёт с переписанными nonce и временем | 0 | 0 | 60 |
| Утечка ключа: подложный отчёт с верным HMAC | 0 | 0 | 0 |

В пяти условиях основной модели угроз K обнаружил 300/300 проверок,
O — 180/300, B — 0/300. Дополнительные 120 обнаружений относятся к двум
условиям подделки содержимого. На 120 нормальных проверках ложных тревог нет.
В отрицательном контроле утечки ключа все варианты пропустили 60/60 нарушений.
При учёте этого контроля вместе с основными нарушениями: K — 300/360,
O — 180/360. Во всех трёх повторах результаты одинаковы.

## Вывод и границы

В этой реализации независимое наблюдение выявляет расхождение фактического
состояния с политикой при неизменном NRF. HMAC даёт отдельный вклад, когда
нарушитель подменяет наблюдение, но не владеет ключом. Это проверка реализации
известного механизма аутентификации сообщений; она сама по себе не доказывает
научную новизну КИЕ или прирост качества Isolation Forest.

Исследовательская NF зарегистрирована в Open5GS, но не является штатной NF
ядра. КИЕ передаётся через межпроцессный канал; подмена моделируется явным
изменением доставляемого конверта в стенде, а не эксплуатацией сетевой уязвимости.
HMAC использует общий секрет, а не асимметричную цифровую подпись. ОС,
наблюдатель и проверяющая сторона доверенные; аппаратная аттестация отсутствует.
Измеряется файл, который сервис действительно читает, а не произвольное
состояние памяти или добросовестность полностью скомпрометированного процесса.

В условиях replay/stale одновременно изменена конфигурация; общий результат
этих условий не изолирует вклад проверки возраста от сравнения хеша.
Короткая серия и заданные воздействия не устанавливают эксплуатационный FPR.
Нагрузка, масштабирование, радиодоступ и длительное поведение здесь не изучались.
Исходный вывод предыдущей серии об отсутствии вклада прежнего КИЕ остаётся в силе:
новый результат относится к изменённому наблюдателю и дополнительным условиям.

После распаковки evidence.zip выполните для каждого seed:

```bash
python experiments/kie_independent/audit.py /path/to/evidence/9101
```

Для нового измерения на изолированном стенде с NRF:

```bash
python -m experiments.kie_independent.run --nrf --seed 9101 --out evidence/9101
```

Без --nrf доступна локальная проверка процессов и механизма; она не считается
измерением на Open5GS. Каталог результата должен быть новым, чтобы не затирать
предыдущие результаты. Исходный общий ключ в архиве одноразовый и лабораторный.
